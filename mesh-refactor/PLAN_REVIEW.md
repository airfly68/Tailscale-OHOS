# MeshArc 改造计划独立审查

## 1. 审查结论

原计划方向基本合理，但不宜按原版本直接进入生产代码实施。主要阻塞是规则来源
文件缺失、部分推荐/可选/示例内容被写成硬性验收、多个 Milestone 同时切换新
实现并删除旧实现，以及数据迁移成功后删除旧数据与“可回退”目标冲突。

本次已直接修订计划：Milestone 0 成为生产代码实施门禁；Common HAR、状态管理
装饰器、分层类名、`FOLLOW_DESKTOP` 和候选断点不再被当成最佳实践的标准答案；
大 Milestone 被拆为单行为切片；旧实现删除和数据清理被移到独立阶段；增加状态
所有权、生命周期、异步过期结果、安全故障注入、设备条件和往返回退证据。

修订后可先执行 Milestone 0。在两份规则文件恢复并核验前，不应开始修改生产
代码的 Milestone。

## 2. 审查范围与限制

本次对项目资料只读取：

- `AGENTS.md`；
- `mesh-refactor/PROJECT_AUDIT.md`；
- `mesh-refactor/APPLICABILITY_MATRIX.md`；
- `mesh-refactor/GOALS.md`；
- `mesh-refactor/EXECUTION_PLAN.md`；
- `mesh-refactor/DECISIONS.md`。

用户指定的 `mesh-refactor/RULE_INDEX.md` 和
`mesh-refactor/RULE_CONFLICTS.md` 实际不存在。仅按精确文件名和
`mesh-refactor/` 目录定位过文件，没有重新扫描项目内容。未读取原始 HTML，
未读取 B01-B05 或其他提取材料，未修改应用代码。

因此，本次可以审查“计划是否正确处理规则级别与适用条件”，但不能独立证明
105 条规则的原始级别和条件是否抄录正确。该证明被明确移入 Milestone 0。

## 3. 关键问题与修订

### P0：规则级别缺少可追溯证据

`APPLICABILITY_MATRIX.md` 声称沿用 B01-B05 原文，但本次指定用于复核的规则索引
和冲突文件缺失。原计划仍允许基于矩阵进入架构改造，存在把整理错误固化为代码
要求的风险。

已修订：Milestone 0 必须恢复来源、级别、适用条件和冲突记录并核对 105 条
结论；完成前禁止修改生产代码。矩阵汇总数量只表示覆盖率，不再等同实施范围。

### P0：迁移回退策略自相矛盾

原 D010 要求迁移验证后删除旧数据，而总目标又要求每个 Milestone 可回退。若旧
版本只认识旧位置，删除后代码回退可能导致数据不可读、重新登录或设备身份变化。

已修订：迁移 Milestone 不删除旧数据；权威用户数据默认不迁移；需要持久恢复的
数据在回退窗口内保持旧位置权威或使用可验证双写；在克隆 fixture/测试沙箱执行
“旧版 -> 新版 -> 旧版 -> 新版”；删除旧数据必须另立未来清理计划。

### P1：推荐项、可选项和示例实现被硬化

原计划把以下内容直接写成完成条件：

- 单 Common HAR 作为“符合最佳实践”的结果；
- 同时引入 Gateway、Coordinator、Repository、ViewModel；
- 新状态统一使用 `@ObservedV2/@Trace`；
- 配置 `FOLLOW_DESKTOP`；
- 补齐 320/1440vp 和 0.8/1.2 阈值；
- 恢复所有 List/Scroll 位置和 Sheet/Dialog 展示状态。

这些内容有的是项目架构选择，有的是推荐/可选能力，有的是候选阈值或实现示例。
它们不能仅因出现在最佳实践或示例中就成为规范答案。

已修订：Common HAR 明确为项目选择且只做最小落地；类名和层数不是验收条件；
V2 状态仅限有收益的新 UI-facing 切片，不迁移全部 V1；`FOLLOW_DESKTOP` 先做
API 23/设备行为核验；候选断点等待产品确认和内容约束证据；仅对实际重建的列表
保存阅读锚点；瞬态覆盖层策略等待确认。

### P1：原 Milestone 范围过大且相互耦合

原 M2 同时包含路径、EL2、临时文件迁移、日志脱敏和 HTTP UI；原 M3/M4 各自
覆盖整套 Home/VPN 与 Tailsend；原 M5 同时拆 Settings、Account、Diagnostics
和 AppShell；原 M7 同时引入窗口环境、断点、三页布局、滚动与覆盖层恢复。
这些阶段无法可靠定位回归，也无法在失败时只回退一个行为。

已修订为小切片：只读 Home 状态、VPN 核心命令、网络路由偏好、Tailsend 发送、
接收/通知、历史/缓存、AppShell/Want、Settings、自定义后端、Account/Diagnostics、
日志脱敏、HTTP 风险确认、文件位置、只观测窗口环境，以及 Home/Transfer/
Settings/跨页安全区四个独立响应式 Milestone。旧实现清理单独进行。

### P1：迁移顺序会放大业务语义风险

原计划在责任边界建立前移动临时文件和改变安全行为，并在同一阶段切换 Common
DTO；AppShell 替换与 Settings/Account/Diagnostics 拆分同时发生；
`BridgeStatus.ets` 可能在全部调用方和生命周期证据完成前删除。

已修订顺序：规则/行为基线 -> 最小契约边界 -> 只记录数据边界 -> 单行为 Feature
切片 -> AppShell 外部入口 -> Settings 等切片 -> 安全/位置行为 -> 主题 -> 只观测
窗口 -> 逐页布局 -> 独立清理 -> SysCap 和最终回归。

### P1：状态管理和生命周期风险原先不可验收

原计划没有要求明确状态唯一所有者、Tab 可见性与 VPN 后台生命周期的区别、
监听器对称注销、重复进入幂等、过期 Promise 完成、通知重入或 UI 线程更新边界。
抽离后可能出现重复连接、重复保存/远端删除、页面销毁后更新和监听器泄漏。

已修订：新增 D017，并在 M0、Home/VPN、Tailsend、AppShell 和窗口 Milestone
增加状态转换表、所有者、generation/token、命名回调、注册计数、冷/热启动、
前后台、系统终止恢复和通知重入证据。Tab/页面隐藏不得停止核心 VPN。

### P1：安全风险不仅是“脱敏和 EL2”

原计划已有较好的 tsnet 保护，但缺少外部 Want 信任边界、文件校验到使用之间的
竞态、远端删除幂等、迁移磁盘不足/原子替换失败以及旧版本可读性验收。

已修订：外部参数必须验证并转换为幂等动作；Tailsend 保留 ArkTS/Go 双边路径
和文件复核；安全 Milestone 增加复制中断、校验失败、原子替换失败、磁盘不足、
缓存清理、系统调用失败和往返回退；秘密读取失败不得生成新凭据或退回明文。

### P2：设备和窗口条件未区分“适用”与“可获得”

原计划把折叠开合、2in1 自由窗、系统标题区和 HDS 材质均写成统一通过条件，
但没有规定设备不可获得时如何记录，容易把未执行写成通过。

已修订：手机/平板/2in1 按可获得矩阵验证；折叠设备不可获得时只用窗口尺寸
变化验证通用连续性，并明确标记未验证；HDS 材质不接受 Previewer 作为通过
证据；脚本和 `STATUS.md` 必须区分通过、失败和未执行。

### P2：部分验收条件不可操作

原计划使用“正常”“不丢状态”“probe 通过”等描述，但没有统一命令、前置条件、
退出码和关键断言。构建成功也不能证明生命周期、远端删除时机或回退安全。

已修订：M0 定义 `scripts/test.ps1` suite 接口并登记现有 probe 的准确命令；每个
Milestone 必须记录退出码、设备/窗口条件、结构化断言、失败注入、未验证项、
代码回退点和数据兼容条件。候选阈值未实施时不生成虚假边界验收。

## 4. 十项检查结论

| 检查项 | 原计划结论 | 修订后处理 |
| --- | --- | --- |
| 推荐项误作强制项 | 存在 | Common HAR、V2、纵向断点、窗口配置均改为项目选择或证据驱动。 |
| 示例代码误作标准实现 | 存在 | 分层类名、模块形态、HDS/断点示例不再作为验收。 |
| 设备/窗口条件 | 不足 | 增加 API 23、目标设备、窗口模式和“未执行”状态。 |
| 无必要大规模重构 | 存在 | 拆成单行为切片，旧实现独立清理。 |
| 业务语义变化 | 高风险 | 增加逐字段/状态/时序 fixture、幂等和生命周期基线。 |
| 迁移顺序 | 不完整 | 先契约与适配器，后切换；安全位置变更在 Feature 抽离后。 |
| 状态/安全/生命周期 | 明显遗漏 | 新增 D017、故障注入、异步过期与所有权要求。 |
| Milestone 独立性 | 不足 | Home、VPN、Tailsend、AppShell、窗口和逐页布局拆分。 |
| 验收可验证性 | 不足 | 统一 suite、命令、退出码、设备条件和结构化证据。 |
| 失败回退 | 存在矛盾 | 迁移不删旧数据，旧实现删除独立，要求前后版本往返。 |

## 5. 仍需产品决定

1. 响应式策略是否采用 320/1440vp 与 0.8/1.2 的候选阈值，还是保留现有
   600/840vp，并只在逐页内容约束证明需要时增加阈值。
2. 窗口布局类别变化时，Sheet/Dialog 等瞬态覆盖层应关闭但保留底层输入，还是
   在组件重建后恢复展示。

这两项不阻塞 Milestone 0-11 的无关工作，但会阻塞对应的 Milestone 12A-12D。
