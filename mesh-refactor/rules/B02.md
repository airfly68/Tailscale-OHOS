## 架构与模块化

### B02-R001

- **规则内容：** 应采用分层架构和模块化设计，以降低层间依赖和模块耦合，并提升可维护性、可扩展性与复用性。
- **级别：** RECOMMENDED
- **来源文件：** S01
- **来源章节：** `架构概览`（正文）
- **可搜索的原文定位片段：** `开发者应关注以下方面的架构设计`
- **适用条件：** 应用规模或业务复杂度增加，需要维护、扩展或测试时。
- **不适用条件：** 来源未说明。
- **涉及的 ArkUI 或 ArkTS API：** 未涉及。
- **是否可能与其他文档冲突：** 否（B02 已读来源未见相反表述；跨批次未知）。

- **规则内容：** 三层架构中，产品定制层承载设备或场景定制；基础特性层承载相对独立的功能 UI 与业务逻辑；公共能力层承载可复用 UI、数据管理、外部交互和工具库。
- **级别：** RECOMMENDED
- **来源文件：** S02
- **来源章节：** `逻辑模型`

### B02-R007

- **规则内容：** 对单 Ability、单窗口或通过多实例/指定实例实现多任务的应用，优先采用单个 Entry 类型 HAP；模块是否使用 HSP 或 HAR 取决于是否需要按需加载。
- **级别：** RECOMMENDED
- **来源文件：** S03
- **来源章节：** `模块化设计理念 > 应用模块化选型 > 按需加载模块`
- **可搜索的原文定位片段：** `优先采用单HAP（Entry类型的HAP）来实现应用开发`
- **适用条件：** 只包含一个 UIAbility，且无需 ExtensionAbility 的应用。
- **不适用条件：** 需要多个 UIAbility 承载多任务，或需要 ExtensionAbility 扩展功能时。
- **涉及的 ArkUI 或 ArkTS API：** `UIAbility`、`ExtensionAbility`；涉及 Entry 类型 HAP、HAR、HSP。
- **是否可能与其他文档冲突：** 否（B02 已读来源按任务形态区分单/多 HAP；跨批次未知）。

### B02-R008

- **规则内容：** 独立运行和安装的模块只能选择 HAP，并作为 App 中的 Feature 类型 HAP 存在。
- **级别：** REQUIRED
- **来源文件：** S03
- **来源章节：** `模块化设计理念 > 总结`
- **可搜索的原文定位片段：** `具备独立运行和安装的模块只能选择HAP包`
- **适用条件：** 某模块需要独立运行及安装时。
- **不适用条件：** 模块不具备独立运行和安装特性时。
- **涉及的 ArkUI 或 ArkTS API：** 涉及 Feature 类型 HAP；若模块承载界面，涉及 `UIAbility`。
- **是否可能与其他文档冲突：** 否（B02 已读来源未见相反表述；跨批次未知）。

### B02-R009

- **规则内容：** 相对独立、且由系统独立 ExtensionAbility 承载的扩展功能，建议使用 Feature 类型 HAP 承载该 ExtensionAbility。
- **级别：** RECOMMENDED
- **来源文件：** S03
- **来源章节：** `模块化设计理念 > UIAbility应用组件设计`
- **可搜索的原文定位片段：** `建议通过Feature类型的HAP承载单独的ExtensionAbility组件`
- **适用条件：** 卡片、分享等扩展功能不作为独立任务或窗口运行，并由 ExtensionAbility 承载时。
- **不适用条件：** 功能需要作为独立任务、独立窗口运行，或不由 ExtensionAbility 承载时。
- **涉及的 ArkUI 或 ArkTS API：** `ExtensionAbility`；涉及 Feature 类型 HAP。
- **是否可能与其他文档冲突：** 否（B02 已读来源未见相反表述；跨批次未知）。

### B02-R012

- **规则内容：** 在多 HAP/HSP 引用同一 HAR、且 HSP 与 HAR 都满足业务需求时，建议将 HSP 改为 HAR 以优化冷启动性能；集成态 HSP 不适用该建议。
- **级别：** RECOMMENDED
- **来源文件：** S03
- **来源章节：** `模块化设计理念 > 应用模块化选型 > 多HAP/HSP引用相同HAR包的影响`
- **可搜索的原文定位片段：** `如果HSP包和HAR包均能满足业务需求，建议将HSP包改为HAR包`
- **适用条件：** 多 HAP/HSP 同时引用相同 HAR，且启动性能是优化目标时。
- **不适用条件：** HSP 为集成态 HSP；或 HSP 与 HAR 不都满足业务需求时。
- **涉及的 ArkUI 或 ArkTS API：** 未涉及；涉及 HAR、HSP。
- **是否可能与其他文档冲突：** 否（B02 已读来源明确以“仅从性能角度”为条件；跨批次未知）。

### B02-R013

- **规则内容：** 用公共 HSP 模块壳减少 HAR 在编译产物中的重复时，应控制模块壳数量，避免过多模块壳影响安装速度和启动性能。
- **级别：** RECOMMENDED
- **来源文件：** S03
- **来源章节：** `模块化设计理念 > 多HAP工程 > 包含公共能力模块`
- **可搜索的原文定位片段：** `模块壳数量不宜过多，否则可能影响安装速度和启动性能`
- **适用条件：** 为最小化 App Size 而采用公共 HSP 模块壳时。
- **不适用条件：** 未采用公共 HSP 模块壳时。
- **涉及的 ArkUI 或 ArkTS API：** 未涉及；涉及 HSP、HAR。
- **是否可能与其他文档冲突：** 否（B02 已读来源将 App Size 与性能作为权衡；跨批次未知）。

- **涉及的 ArkUI 或 ArkTS API：** 未涉及；涉及 HAR、HSP、bundleName。

### B02-R018

- **不适用条件：** 文件必须在用户解锁前访问（如时钟、闹铃、壁纸）时，可使用 EL1。
